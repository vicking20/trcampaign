# Origin / LSX launcher

## Why a launcher is required

The retail game contains the old Origin SDK (Ebisu). Before entering the online flow it expects a local Origin-style LSX service on the player's PC. This is separate from the remote Blaze server.

`nfsrun-launcher.exe` acts as the small local compatibility process the game expects.

## What the launcher does

On each player PC the launcher:

1. logs in to the server over HTTPS with the player's key (see
   [LOGIN.md](LOGIN.md));
2. opens an LSX endpoint, normally `127.0.0.1:3216`;
3. performs the expected challenge/crypto/message flow;
4. hands the game one-time login codes;
5. prepares `NFSTR_lsx<port>.exe`, its patched copy of the game
   ([CLIENT_PATCHING.md](CLIENT_PATCHING.md#copy-made-by-the-launcher)), and
   writes the game language to `HKCU\Software\EA Games\Need for Speed(TM) The Run`;
6. starts the copy when the player presses **PLAY**, with Origin-style
   environment variables (`EALsxPort`, `EAAuthCode`, `EAGameLocale`, ...);
7. stays alive while the game runs; closing it closes the game;
8. relays the server's friends, presence and invites as LSX events.

The launcher is built as **32-bit**, like the game. It starts no program
other than the game: registry values and port checks use the Windows API
directly.

### Permission

Before the first change on the PC the launcher lists what it will do and
asks once (a Yes/No box; `-console`: `y/n`):

| Item | When |
|---|---|
| create the game copy | always (default) |
| set the game language | always |
| change the playlist data | `EXTRA_PLAYLISTS=1` |
| write the Origin registry values (administrator) | `NO_ORIGIN_START=0`, original exe |

The answer is stored as `ALLOWED=` in `nfsrun-launcher.key`; a new item is
asked again. Without permission the launcher does not start the game.

## Launcher window

The launcher is a native Win32 window (through `syscall`, no cgo, painted
with GDI). Texts come from `cmd/nfsrun-launcher/i18n.go` in 14 languages,
chosen by `LANGUAGE` (which also sets the game's language, see
[CONFIGURATION.md](CONFIGURATION.md#nfsrun-launcherini-player)).

- **Player card:** the name; the server state (online, offline, connecting,
  not configured) without its address, following the live channel; the
  local LSX address and, for a second copy on one PC, the copy number.
- **Friends card:** the server's player list, online first. Presence:
  `JOINABLE` = in a match, other online states = in game, else offline.
  While the server is offline the card says so instead of showing a stale
  list.
- **PLAY:** starts the game (Enter works too); "IN GAME" while it runs. The
  launcher stays open after the game exits.
- **Show log / Settings / Open folder:** the log inside the window, the
  `.ini` in Notepad (restart the launcher after a change), the launcher
  folder.
- **Errors** that stop the launcher (login failed, game not found, name too
  long) show on the status line and disable PLAY.

Closing the launcher closes the game (it asks first while the game runs).
The game also runs in a job object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`,
so it ends when the launcher is killed or crashes too.

`-console` gives a text window that starts the game at once and exits with
it. A launcher started by the game's Origin SDK, and `-lsx-only`, only serve
LSX (no PLAY).

The exe has an icon, version information and a manifest (asInvoker,
per-monitor DPI v2, Common Controls 6) from
`cmd/nfsrun-launcher/rsrc_windows_*.syso`, generated by
`go run ./cmd/mkwinres`. Build flags: `-ldflags "-s -w -H windowsgui"`.

## Login

On first start the launcher creates `nfsrun-launcher.key` with a random
32-byte Ed25519 seed (`CLIENT_KEY=`). It never leaves the PC; the server
stores only the public key. The launcher signs a one-use server challenge
(`POST /nfsrun/auth/challenge`, then `POST /nfsrun/auth/session`) and gets a
short-lived session ticket, renewed by signing again.

The game never sees the ticket. Each time it asks LSX for an auth code, the
launcher fetches a one-time game code (`POST /nfsrun/auth/gamecode`, header
`X-NFSRun-Session`):

```text
nfsrun-g1.<32 hex>     valid 5 minutes, single use, at most 8 open per persona
```

Blaze `Authentication.login` / `originLogin` consume the code and issue a
separate Blaze session key for that connection. A name, a hostname or an
`eatest.<machine>@ea.com` email is never a credential. The only exception is
an EA app/Origin login that carries no code: it maps to the single launcher
active on the same public IP, and is refused when several are.

New names need an invite code with `AUTH_MODE=invite` (default); details and
lost keys: [LOGIN.md](LOGIN.md).

## Launcher configuration

Every `nfsrun-launcher.ini` key and command-line option:
[CONFIGURATION.md](CONFIGURATION.md#nfsrun-launcherini-player). The launcher
of a player package has the server's address, certificate pin and domain
built in (`nfsrun-server --stamp-launcher`, see
[LAUNCHER_HTTPS.md](LAUNCHER_HTTPS.md#launcher-preset)); a generic build has
none. The advanced keys `SERVER_HTTP` / `SERVER_CERT_PIN` / `BASE_DOMAIN` in
the `.ini` override them.

## Friends and presence

The launcher exposes the private server's player/friend state to the game as Origin social data.

It uses the server HTTP API to get the initial state and keeps a live stream open at:

```text
GET /nfsrun/stream?persona=<name>
X-NFSRun-Session: <server-issued session key>
```

That channel can deliver:

- friends coming online/offline;
- presence state changes;
- group/playgroup state;
- invites.

Polling remains a fallback if the stream is interrupted.

The server persists friend relationships in MariaDB. Depending on configuration, it can also expose all server users as friends for small private communities.

## Groups and invites

The Multiplayer Group menu combines Blaze Playgroups with LSX/Origin-style social events.

Invites work as with Origin:

1. The inviter's game sends `SendInvite` (invitees only; `Invitation` is empty). The launcher relays it to the server with the inviter's presence `SessionId`, which the game sets to its own Blaze id while joinable.
2. The invitee's launcher plays Origin's part: with `INVITES=ask` it shows a Yes/No box, with `auto` it accepts at once, with `off` it ignores the invite.
3. On accept it sends the game the event Origin sends for an accepted invite:

   ```xml
   <MultiplayerInvite version="2" initial="false" from="1000001">
     <SessionInformation>1000001</SessionInformation>
   </MultiplayerInvite>
   ```

   `SessionInformation` is a child element (the SDK reader at `0x01920D30`); an attribute is ignored and the game then looks up an uninitialised id.
4. The game looks the inviter up (`UserSessions.lookupUser`) and reads the game and playgroup it is in from `EDAT.ULST` (`fb::BlazeInviteAcceptedHandler::onUserLookup`): it leaves its own group or game if they differ, then joins the inviter's playgroup, or the inviter's game by name (`joinGame` with GID 0 and USER).

## Two games on one PC

A second launcher started while one runs uses the next LSX port (`3217`,
...), its own copy `NFSTR_lsx3217.exe`, the name `<PLAYER_NAME>_2` (unless
`-persona` is given) and `nfsrun-launcher-2.log`. For testing.

## Logging

Launcher logs are written next to the launcher executable, normally:

```text
nfsrun-launcher.log
nfsrun-launcher-2.log
...
```

The log records LSX requests, friend-stream activity, registry and startup state and the game process exit result. The last 500 lines are also shown by "Show log" in the launcher window.
