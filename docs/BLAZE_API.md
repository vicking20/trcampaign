# Blaze API of Need for Speed The Run (from the game itself)

Generated by `tools/blaze_schema/gen_doc.py` from `source/internal/blaze/schema.json`.
Nothing here comes from other emulators or SDK dumps of other games:

* **Ids and names** — the PC exe's own getCommandName / getNotificationName switches.
* **Request / response / error types** — the `RpcJob<Response, Error>` each call site of the
  PS3 build constructs, and the request type in the call signature (DWARF).
  `name` = taken from the generated class names because no call site exists (marked *).
* **Members** — the TdfMemberInfo tables (tag, kind, default) + DWARF member names, checked
  against the PC exe's tables (712 of 716 identical). NFS-specific types (Autolog, game
  reports) are read from their `visit()` code, PC first.
* **Notifications** — the decoder each `handleNotification` case calls (PS3).

How the client decodes (`Heat2Decoder::getHeader`, PS3 `0x012E41C4`): members in ascending tag
order; the same tag with another wire type is a decode error (the rest of the reply is lost);
lower/unknown tags are skipped; a missing member keeps its default. The server now checks every
packet it sends against this schema and logs `[SCHEMA]` lines with `SCHEMA_CHECK=true`.

Column *server*: what this server answers — `yes`, `empty reply` (a reply with no members),
`error reply`, `—` (not implemented: an empty success).
